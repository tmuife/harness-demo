# Harness 讲解结构建议

若只能选择一套框架讲解 Harness，优先使用现有的 6 个 Demo：它们直接说明 Harness 让模型获得了什么能力，以及工程结果如何变化。

```text
Understand → Act → Prove → Control → Continue → Ground
理解        行动    验证    控制     延续      依据
```

11 个组件适合作为第二层，解释这些能力在系统内部如何实现。两者不应一一对应：Demo 是用户可感知的能力，组件是底层实现模块。

| 讲解层 | 使用内容 | 回答的问题 |
| --- | --- | --- |
| 第一层：能力与结果 | 6 个 Demo | Harness 为什么让工程任务更可靠？ |
| 第二层：系统实现 | 11 个组件 | Harness 如何提供、约束和验证这些能力？ |

## 建议的组件分层

```text
输入与知识
├─ 提示词构建、上下文管理、记忆、外部依据

运行与行动
├─ 编排循环、输出解析、工具系统、错误处理

可靠性与治理
├─ 状态管理、验证循环、护栏与安全

规模化协作
└─ 子智能体编排
```

## Demo 归属

- Demo 1：输入与知识
- Demo 2：运行与行动
- Demo 3：可靠性与治理中的验证
- Demo 4：可靠性与治理中的安全
- Demo 5：输入与知识中的记忆，并涉及状态管理
- Demo 6：输入与知识中的外部依据

## 注意

“外部依据（Grounding / Retrieval）”应明确作为一个组件：工具是获取信息的手段，外部依据才是 Demo 6 展示的核心价值。
