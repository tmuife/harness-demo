## Why

当前 Harness 演示只能通过命令行逐个运行，观众需要在不同终端输出之间自行理解模型获得的能力、执行过程和最终结果。需要一个可视化对照界面，将同一任务在 PLAIN 与 Harness 配置下的输入、行动轨迹和工程证据并排呈现，使六类 Harness 能力的作用更直观、可解释。

## What Changes

- 新增独立的 React + TypeScript 前端服务，以“能力对照实验台”的形式展示 Harness 演示。
- 提供六个 Harness 能力选择项：项目上下文、受限工具行动、测试反馈循环、边界与审批、跨会话状态和外部依据。
- 对同一个任务并排展示固定 PLAIN 基线与当前 Harness 配置的运行状态、对话/事件时间线和结果差异；后续组合模式仍保持 PLAIN 基线，不提供任意配置 A/B 对照。
- 两侧实验按 PLAIN、HARNESS 的顺序执行，保持现场讲解顺序并降低模型服务并发限流风险。
- 展示可验证的工程证据，包括输入来源、LLM 调用、工具活动、文件修改、测试反馈、审批、会话交接、外部依据及最终 PASS/FAIL。
- Demo 4 的人工审批使用时间线内联审批卡片，保留操作请求、审批和后续执行的因果顺序。
- 第一阶段使用浏览器 `sessionStorage` 记录最近一次实验 ID，并由后端在内存中短期保留运行状态和结果，不引入数据库。
- 第一阶段仅允许选择一个已实现的能力进行真实运行；尚未实现或不可组合的配置显示明确的不可用原因，不生成伪造结果。
- 为前端定义结构化实验与事件接口边界，后续由 Python 后端适配现有 Demo 运行逻辑并通过流式事件提供进度。
- 保留现有命令行演示能力；Web UI 是新增入口，不改变当前 CLI 的行为。

## Capabilities

### New Capabilities

- `harness-comparison-web-ui`: 覆盖六类 Harness 能力的选择、PLAIN/Harness 并排运行视图、实时事件时间线、证据展示、结果对比以及不可用状态说明。

### Modified Capabilities

无。

## Impact

- 新增 `frontend/` React + TypeScript + Vite 工程及后续页面代码。
- `backend/` 已包含现有 Python 演示；后续需要在该服务中增加实验创建、事件流和结果查询接口。
- 前端不得接触 `.env`、API Key、任意文件系统路径或任意命令执行能力；这些继续由后端安全边界负责。
- 第一阶段复用当前已实现的 Demo 1 至 Demo 3；Demo 4 至 Demo 6 在后端实现前只展示为“设计中/不可运行”。
