## Why

架构探索首页需要完整的组件职责、共享业务背景和各 Demo 的具体任务，而当前后端仅提供嵌在能力中的组件 ID/标题、简短 TaskBrief 以及共享生成的任务完成条件。前端效果经用户确认后，将这些教学业务元数据收敛到后端，可以减少前端重复文案，并使任务要求准确对应六个 Demo 的实际行为。

## What Changes

- **实施前置条件：** `add-harness-architecture-explorer` 已实现并完成效果展示，用户明确决定继续后端调整；当前仅创建规划文档，不授权实施。
- 提供只读 `/api/harness-components` 目录，完整返回 11 个组件的稳定 ID、名称、职责、教学分组和覆盖状态，包括暂无独立 Demo 的子 Agent 编排。
- 在现有 `/api/task` 中增补业务背景与共享约束，在 `demoTask` 中增补明确的任务目标，并逐项校正完成条件；保留现有公开字段、能力 ID 和主要/支撑映射。
- 组件关联 Demo 继续从现有能力映射推导，不建立另一套关系表；架构坐标、连线布局和视觉状态仍由前端负责。
- 包含必要且有限的前端数据接线：优先使用新目录和任务字段，在旧服务或新目录不可用时沿用第一阶段展示适配，使后端改动可以在已验收界面中验证。
- 增加目录一致性、任务语义、旧 API 兼容和接线回退的确定性测试，保持模型执行、PLAIN/HARNESS 实验条件、审批、结果和 SSE 不变。

## Capabilities

### New Capabilities

- `harness-exploration-catalog`: 支撑架构探索的完整组件目录、公开业务背景、Demo 任务目标及兼容接入契约。

### Modified Capabilities

无。现有实验请求、执行和结果要求保持不变；新增元数据及其前端接入由新 capability 约束。

## Impact

- 主要影响 `backend/src/harness_demo/web/catalog.py`、`models.py`、`app.py` 及后端测试；仅在前端的类型、API 和展示适配层接入扩展字段，不重新设计页面。
- 新接口和字段是兼容性扩展，不引入数据库、通用工作流引擎、真实外部 provider 或额外 LLM 调用。
- 本 change 依赖前端评审结果；若评审改变所需字段，应先更新本 change 的规格、设计和任务再实施。
- 不补做子 Agent Demo，不把教学组件冒充独立运行模块，也不加入缺乏事件证据的执行动画。精确组件追踪如后续需要，应单独确定范围。
