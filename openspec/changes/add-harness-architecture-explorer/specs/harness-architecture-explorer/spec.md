## ADDED Requirements

### Requirement: 以教学架构作为首页入口
系统 SHALL 在首页主要区域展示 11 个 Harness 教学组件及分组，明确 Harness 边界与用户任务、模型、工作区/测试环境、外部依据等交互对象。系统 MUST 标注教学架构性质，MUST NOT 将外部对象计入 11 个组件或将连线呈现为本次真实执行轨迹。

#### Scenario: 首次浏览总览
- **WHEN** 用户进入页面且核心目录加载成功、没有待恢复实验
- **THEN** 页面展示共享业务场景、教学架构和选择引导
- **AND** 开始对照保持禁用，直到选中可运行 Demo

#### Scenario: 查看组件关系
- **WHEN** 用户选中一个架构组件
- **THEN** 页面突出该组件及相关教学关系，并展示文字职责说明
- **AND** 选择操作不创建实验、不调用 LLM

### Requirement: 从组件选择关联的单个 Demo
系统 SHALL 使用稳定组件 ID 从服务端 primary/supporting 关系推导关联 Demo，区分主要和支撑关系。系统 SHALL 优先推荐可运行的主要关联，其次推荐可运行的支撑关联，同级按 Demo 编号、缺失时按能力 ID 稳定排序。系统 MUST NOT 暗示 11 个组件分别拥有独立 Demo。

#### Scenario: 一个组件关联多个 Demo
- **WHEN** 用户选择同时主要关联 Understand 和 Ground 的上下文管理
- **THEN** 侧栏展示至少这两个实验选项及其关系，默认推荐 Understand
- **AND** 用户选择 Ground 后，任务预览和待运行 capability 同步切换到 Ground

#### Scenario: 从支撑组件进入实验
- **WHEN** 用户选择输出解析
- **THEN** 页面展示其支撑的 Act 实验，并说明观察结构化工具调用和参数校验
- **AND** 不宣称存在独立的输出解析 Demo

#### Scenario: 切换组件时保留有效选择
- **WHEN** 用户切换组件且当前 Demo 仍是新组件的关联 Demo
- **THEN** 当前 Demo 保持选中
- **AND** 若不再关联，则选择新组件的推荐可运行 Demo 或清空选择

#### Scenario: 组件没有演示覆盖
- **WHEN** 用户选择子 Agent 编排
- **THEN** 页面展示职责及“暂无独立演示”说明
- **AND** 没有可启动 Demo，不生成模拟结果

### Requirement: 分层呈现业务背景与当前实验任务
系统 SHALL 在顶部展示共享业务场景及可访问的“查看业务背景”入口，并在选中 Demo 的侧栏直接显示任务目标、PLAIN 条件、HARNESS 条件和观察重点。系统 SHALL 提供“查看完整任务”入口展示完成条件、预期证据和讲解提示；摘要与完整详情 MUST 使用同一规范化展示数据。

#### Scenario: 查看共享业务背景
- **WHEN** 用户打开业务背景
- **THEN** 页面展示公开的运费升级场景和共同约束
- **AND** 不把所有 Demo 都描述为写入文件并通过实现测试

#### Scenario: 直接预览任务
- **WHEN** 用户选中任一可用 Demo
- **THEN** 无需打开弹窗即可读到该 Demo 的目标、两侧条件及观察重点
- **AND** 进入完整详情时，目标与条件不发生矛盾

#### Scenario: 不同 Demo 的任务语义
- **WHEN** 用户依次查看六个 Demo
- **THEN** Understand 表达只读分析，Act 区分建议和执行，Prove 不保证先失败后修复，Control 区分门禁与任务结果，Continue 说明会话交接，Ground 明确本地模拟依据
- **AND** 任务说明不预先承诺运行成功，也不冒充本次运行结论

#### Scenario: 查看观察重点对应的证据
- **WHEN** 用户启动实验并查看任务预览中的观察重点
- **THEN** 页面提供对应已有阶段或证据区域的可识别定位方式
- **AND** 证据尚未出现时显示中性状态，不生成示例执行记录充当真实结果

### Requirement: 在现有后端上独立完成前端体验
本阶段前端 SHALL 使用当前核心目录和实验接口，MUST NOT 要求新增后端接口或修改 backend 文件。缺失的组件教学解释、分组和任务摘要 SHALL 集中在类型明确的展示适配层；可用状态、关联关系和运行事实 MUST 以现有服务端数据为准。

#### Scenario: 连接当前后端
- **WHEN** 后端只提供当前 `/api/capabilities`、`/api/task` 及实验接口
- **THEN** 架构、业务背景、任务预览和真实实验联动均可使用
- **AND** 前端不请求未来的组件目录接口

#### Scenario: 展示字段缺失
- **WHEN** 某项能力缺少 demoTask 或可选教学字段
- **THEN** 页面使用明确的已知教学摘要或“暂无详细说明”等回退
- **AND** 不伪造运行证据，可运行性仍由服务端能力状态决定

### Requirement: 保持探索视图和实验结果的正确归属
系统 SHALL 在开始实验后以工作台为主体，并将架构收为紧凑导航。结果、证据、审批和实验标题 MUST 绑定服务端 experiment.capabilityId；浏览焦点与实际运行配置 MUST 分开管理。运行期间系统 SHALL 保持审批可见并锁定配置切换与再次启动。

#### Scenario: 实验等待审批
- **WHEN** Control 的 HARNESS 侧等待人工决定
- **THEN** 当前工作台显示可操作的内联审批卡片
- **AND** 不能通过切换到总览隐藏必要审批，任务详情仍可只读查看

#### Scenario: 完成后返回架构图
- **WHEN** Act 完成后用户返回总览并选择安全防护及 Control
- **THEN** 侧栏显示 Control 任务，而最近结果入口仍明确标记 Act
- **AND** Act 的结果不被呈现为 Control 的结果，用户可重新进入最近实验

#### Scenario: 刷新恢复运行
- **WHEN** 最近实验仍存在且处于运行状态
- **THEN** 页面根据服务端 capability 恢复工作台并继续事件订阅
- **AND** 组件焦点缺失不妨碍正确恢复实验或待审批卡片

#### Scenario: 实验过期或启动失败
- **WHEN** 保存的实验已过期或启动请求失败
- **THEN** 页面展示原因并允许回到可选择、可重试状态
- **AND** 不把陈旧结果标为当前新实验，也不永久锁定开始操作

### Requirement: 架构探索支持投屏移动端和辅助技术
系统 SHALL 在桌面使用可读的架构与侧栏布局，在窄屏使用完整的分组组件列表和任务预览。所有节点、实验选项、任务入口和视图切换 MUST 支持键盘及可见焦点，状态 MUST 同时有文字或语义标签；非必要动画 SHALL 遵循 prefers-reduced-motion。

#### Scenario: 使用键盘完成选择
- **WHEN** 用户仅使用键盘选择组件、关联 Demo 并查看完整任务
- **THEN** 所有操作可以完成，选中状态可被辅助技术识别
- **AND** dialog 支持 Escape、焦点约束和关闭后焦点返回

#### Scenario: 窄屏或减少动画
- **WHEN** 页面位于约 390px 宽视口或开启减少动画
- **THEN** 组件、任务摘要、开始按钮和审批均可访问，主页面无横向溢出
- **AND** 减少动画不丢失关系、状态或操作反馈

#### Scenario: 桌面投屏阅读
- **WHEN** 在 1280px 与 1440px 宽桌面检查首页
- **THEN** 组件标题、当前任务和关键操作清晰可读，连线不遮挡文字或控件
- **AND** 长条件和证据在受控区域呈现，不将架构挤压到不可用
