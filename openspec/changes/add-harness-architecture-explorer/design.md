## Context

`HarnessLab` 当前将 `CapabilityPanel`、公共 `TaskBrief`、运行按钮、对照结果和底部 `ComponentMap` 放在同一页面。`Capability` 已包含 `demoTask`、`primaryComponents` 和 `supportingComponents`；`ExperimentResult.capabilityId` 标识实际运行配置。后端没有独立的完整组件目录，`subagents` 仅有未覆盖说明；`TaskBrief` 只有 ID、标题、摘要，部分 Demo 任务完成条件仍使用共享文案。

用户要求先实施前端、查看效果，再决定是否继续后端。本 change 必须在当前后端上完成完整体验，不能依赖第二个 change 的接口。现有两个未归档 change 的已实现交互仍是回归基线；同步规格时需保留其语义事件、阶段对照和任务详情要求。

## Goals / Non-Goals

**Goals:**

- 首页能直接解释 Harness 架构，并通过组件找到合适的真实 Demo。
- 将共享业务背景与当前实验任务分层展示，任务摘要无需打开弹窗才能阅读。
- 保留六个 Demo 的主要/支撑关系、真实对照、控制审批、结果证据和恢复能力。
- 仅前端改动即可独立交付视觉和交互验收。

**Non-Goals:**

- 不拆分成 11 个 Demo，不新增子 Agent 演示，不支持多能力组合。
- 不改后端及实验语义，不增加精确组件执行追踪或自动播放的假运行过程。
- 不实现拖拽编排、自动布局编辑器、数据库历史、离线模拟实验或新的路由框架。

## Decisions

### 1. 首页采用架构画布与任务侧栏，实验态复用工作台

顶部显示“围绕配送政策变更，分析或修改运费计算逻辑”的场景摘要和“查看业务背景”。桌面主区域为架构画布与组件/任务侧栏；未选择时侧栏给出简短引导。移动端改为分组组件列表和其后的任务预览。

开始对照后，架构收为紧凑导航，保留所选组件、Demo 与任务入口，主空间交给现有 `ResultSummary`、`ComparisonLanes` 和证据。完成后可以返回总览，也可以再次进入最近实验；仅保留当前 session 已有的最近一次实验，不扩展为历史库。

采用单页视图状态而不是新路由，可复用当前 reducer、SSE 生命周期和 sessionStorage 恢复。运行期间不切换到隐藏审批的总览页面；任务详情仍可只读查看。

### 2. 图表示教学关系，使用固定布局与语义化按钮

展示编排循环、工具系统、记忆系统、上下文管理、提示词构建、输出解析、状态管理、异常处理、安全防护、质量验证、子 Agent 编排 11 个节点。建议分组为：

| group ID | 教学分组 | 组件 |
| --- | --- | --- |
| `orchestration` | 编排 | 编排循环、子 Agent 编排 |
| `information` | 信息准备 | 上下文管理、提示词构建 |
| `execution` | 行动执行 | 输出解析、工具系统 |
| `verification` | 验证与恢复 | 质量验证、异常处理 |
| `continuity` | 连续性 | 记忆系统、状态管理 |
| `control` | 控制边界 | 安全防护 |

Harness 边界外展示用户任务、LLM、工作区/测试环境和外部依据；这些不是新增的第 12–15 个组件。编排居中，安全作为跨流程控制关系，其他分组围绕主流程组织，避免把全部组件画成必经线性调用链。图标明“教学架构”，默认仅保留关键关系，选中后突出相关节点/连线。

采用 HTML 按钮承载节点，CSS 排布，SVG 仅画装饰性连线。相比图编辑器依赖，这符合固定 11 节点的投屏场景，也便于焦点、文本标签和移动端适配。颜色不独自表达主要、支撑、未覆盖或选中状态。

### 3. 组件选择和 Demo 选择是两个状态

`selectedComponentId` 表示探索焦点，`selectedCapabilityId` 表示待运行 Demo。组件关联关系从服务端能力的 primary/supporting 数组反向推导，不能靠组件标题匹配。

- 列出全部关联 Demo，主要关联在前、支撑关联在后，同级按 `demoTask.number`，缺失时按能力 ID 稳定排序。
- 推荐第一项 available 的主要关联；没有时推荐第一项 available 的支撑关联；一对多时显示显式单选实验选项。
- 切换组件时，如当前 Demo 仍有关联则保留，否则采用推荐项。无可运行关联时清空待运行选择。
- 子 Agent 编排可查看职责，但明确“暂无独立演示”，不产生实验请求。
- 每次请求仍提交单个 capability ID。组件选择、Demo 选择、详情展开均不调用创建实验接口。

沿用 reducer 管理实验状态；仅被侧栏使用的展开状态放在局部组件。不能以多个勾选框暗示可同时启用多个组件。

### 4. 任务分为公共背景、直接预览、完整详情

公共背景只承载业务场景和跨 Demo 成立的约束，不把“所有任务都写文件/都通过测试”作为通用承诺。侧栏预览随 Demo 更新，直接展示任务目标、两侧条件和观察重点；完整详情继续利用现有 dialog 的焦点约束、Escape、关闭和焦点恢复。

| Demo | 任务目标摘要 | 必须保持的语义 |
| --- | --- | --- |
| Understand | 分析升级需求和项目规则 | 只读分析，以规则识别及未修改工作区评价 |
| Act | 展示建议如何变成真实修改与验证 | PLAIN 仅建议，不能描述为已写文件 |
| Prove | 实现规则并用测试反馈修复 | 首轮通过可能无需反馈，不保证发生失败 |
| Control | 在范围和审批约束下完成修改 | 拒绝可体现门禁生效，任务可能未执行 |
| Continue | 调查后通过交接让下一会话续做 | Session A/B 隔离，handoff 限本次工作区 |
| Ground | 根据当前版本政策实现规则 | provider 是本地模拟，非真实联网 |

“观察重点”使用已有 `expectedEvidence` 和 evidence 摘要；进入实验后可定位现有相应阶段/证据区域，不生成新的评价指标或虚构尚未出现的证据。缺失证据使用现有中性说明。

### 5. 将现有数据规范化为前端展示模型

在 feature 内设置一个集中、类型明确的展示适配模块：原始 API 类型保留，规范化后的组件、任务预览供所有页面区域复用。

- 能力状态和 Demo—组件关系以现有服务端字段为准，不在前端硬编码六项永远 available。
- 组件布局、分组、教学职责、`subagents` 未覆盖节点和六项简短任务目标可在前端集中声明。
- 已有 `plainCondition`、`harnessCondition`、`expectedEvidence` 等直接复用；当前共享 completionDefinition 对 Understand 等表达过宽时，在适配层以已确认 Demo 行为提供明确展示文案，并供预览和完整详情一致使用。该文案是教学说明，不参与结果计算。
- 字段缺失时展示可读回退，不臆造业务阈值、内部 prompt、运行记录或成功结果；已知能力仍可按服务端状态运行。
- 第一阶段不请求 `/api/harness-components`，不要求后端增补字段。第二个 change 若实施，仅替换适配数据来源，保留布局逻辑。

相比散落 JSX 文案或一次性 mock 后端，此方式可独立验收且便于后续收敛。

### 6. 浏览焦点与实际运行归属分离

运行中锁定组件/Demo 配置和再次启动，保留任务只读入口和内联审批可见性。实验摘要、证据和标题始终绑定 `experiment.capabilityId`，不能用浏览选择替换结果归属。

完成后返回总览并选择其他组件时，最近实验可通过明确标有原 Demo 的入口查看，不在新任务侧栏下展示旧实验结论。刷新恢复运行中的实验时直接进入工作台并恢复正确 Demo；组件选中不是实验执行身份，缺失时可根据该 Demo 的主要关联恢复默认焦点。恢复过期和启动失败后应可重试/重新选择，不陷入不可操作状态。

## Risks / Trade-offs

- [11 节点和连线使首页拥挤] → 分组、短标题、关键连线、选中聚焦，移动端切换列表，投屏检查文字尺寸。
- [教学架构被理解为真实模块部署图] → 明确图的性质、外部对象和未覆盖组件，不展示伪运行状态。
- [第一阶段展示元数据与后端重复] → 集中适配，记录需收敛字段，第二阶段在用户决定继续后替换来源。
- [切换组件使旧结果误归属] → 明确分离浏览选择与 experiment.capabilityId，并测试恢复与返回路径。
- [入口重构影响审批或可读性] → 复用现有工作台组件，保留可读性和六 Demo 回归测试。
- [旧 change 后续同步覆盖本次 delta] → 同步顺序为已有可读性、六 Demo 完善、再本 change；同步时审查同名 requirement，当前不自动同步或归档。

## Migration Plan

1. 实施前核对当前实现与已有测试，限定改动在前端及必要的前端 README。
2. 实现展示适配、架构导航、任务预览及实验态联动，保持旧 API 可运行。
3. 运行前端 lint、test、build，并检查桌面/移动端、键盘、减少动画、六种任务和 Control 内联审批。真实运行仅在具备已授权环境时排练，不把未排练记为已通过。
4. 向用户展示页面效果、检查结果和仍需后端收敛的数据项，结束本 change 的交付；后端 change 保持未实施。
5. 若用户要求撤回界面，回退本次前端改动即可；无需变更后端、数据或工作区。

## Open Questions

- 前端视觉验收后，用户是否保留该交互并决定实施后端 change？这是交付后的产品决策，不阻塞当前前端方案。
- 首版不加入精确执行追踪；如果用户评审后需要动态联动，需另行确定可由真实事件支持的范围。
