## Why

当前实验页面把 CLI 控制台输出按行转换为时间线事件，模型正文、代码 Diff 和测试日志因此占据主要阅读空间。用户难以先看到本次对照的结论、能力带来的差异以及支撑结论的关键证据，需要将页面从原始事件查看器调整为渐进式的实验讲解界面。

## What Changes

- 实验完成后优先展示带有“本次运行”限定语的自然语言观察结论，并明确区分分析、仅提案、验证失败和基础设施异常。
- 为 Understand、Act、Prove 分别展示符合其演示目标的 PLAIN/HARNESS 对照指标，而不是只展示通用结果和模型调用次数。
- 将默认过程视图收敛为输入、行动、验证、反馈和结论等语义步骤，并在两侧按阶段对齐关键差异。
- 将完整模型输出、Diff、测试日志和协议字段降级为按需展开的结构化证据，同时保留完整运行记录供排错使用。
- 调整后端 Web 事件适配，使一次有意义的操作形成一个结构化事件，控制台输出行作为有界证据附属于事件，不再逐行占据默认时间线。
- 保持现有 CLI 输出、SSE 排序与恢复、安全脱敏、输出截断和真实 LLM 对照语义不变。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `harness-comparison-web-ui`: 修改实时过程和最终结果的展示要求，增加能力定制摘要、语义事件、阶段对齐、结构化证据和完整记录视图。

## Impact

- 后端：`backend/src/harness_demo/web/` 的事件模型、Demo 事件适配和最终结果快照；现有 CLI Demo 行为不变。
- 前端：`frontend/src/features/experiment/` 的类型、状态归并、结果摘要、过程对照和证据展示组件。
- API：SSE 事件和结果快照将增加用于讲解与能力定制指标的结构化字段；现有标识、顺序、恢复和安全边界继续保留。
- 测试：需要补充语义事件聚合、能力指标、结果措辞、证据折叠、完整记录以及可访问性验证。
