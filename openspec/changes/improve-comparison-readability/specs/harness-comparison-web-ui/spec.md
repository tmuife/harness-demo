## MODIFIED Requirements

### Requirement: 通过结构化语义事件实时展示进度
后端 SHALL 通过 SSE 提供有序、可恢复的实验事件。每个事件 MUST 表示一次有意义的输入准备、模型调用、工具操作、文件写入、测试、反馈或结果，而不是单独一行控制台文本；事件 MUST 包含稳定事件 ID、实验 ID、运行侧、受控 stage、status、单调 sequence、时间、标题、讲解摘要和与该 stage 匹配的有界证据。模型正文、Diff 和测试输出的连续文本 SHALL 作为事件证据保存，不得拆成默认时间线中的逐行事件。

#### Scenario: 接收实时语义事件
- **WHEN** 后端产生 input、llm、tool、write、test、feedback、approval、handoff、grounding、result 或 error 操作
- **THEN** 前端将一项操作追加为对应运行侧的一条关键步骤
- **AND** 按 sequence 排序并按事件 ID 去重

#### Scenario: 操作产生长文本输出
- **WHEN** 模型回答、文件 Diff 或测试输出包含多行文本
- **THEN** 默认过程视图只展示该操作的有界摘要
- **AND** 经过脱敏和截断的多行内容作为同一事件的证据按需展开

#### Scenario: SSE 临时断开
- **WHEN** 事件连接在实验未结束时断开
- **THEN** 页面保留已有事件并显示重连状态
- **AND** 前端使用最近事件 ID 恢复连接，避免重复展示

#### Scenario: 接收终态事件
- **WHEN** 实验到达完成或失败终态
- **THEN** 前端停止重连并查询最终结果快照
- **AND** 使用快照校准可能遗漏的末尾事件、能力指标和汇总数据

### Requirement: 按阶段对照过程并分层展示工程证据
页面 SHALL 将两侧事件归入获得信息、采取行动、执行验证、接收反馈和形成结论等稳定阶段，并在完成态优先按阶段对齐 PLAIN 与 HARNESS 的关键差异。获得信息和形成结论 SHALL 始终显示；页面 MUST 显示所选能力的焦点阶段以及任一侧实际产生事件的阶段，并 SHALL 省略两侧均无事件且与所选能力无关的阶段。默认讲解视图 SHALL 展示语义步骤和摘要；完整模型输出、工具参数与结果、文件 Diff、测试日志、事件元数据和协议字段 SHALL 仅在证据详情或完整记录视图中显示。

#### Scenario: 桌面端查看运行过程
- **WHEN** 视口具备并排展示空间且实验正在运行
- **THEN** 页面并排展示 PLAIN 与 HARNESS 当前状态和已完成的语义步骤
- **AND** 长文本输出不直接扩展为多条过程事件

#### Scenario: 完成后比较关键阶段
- **WHEN** 两侧均已到达终态
- **THEN** 页面按相同阶段对齐两侧关键步骤和能力插入点
- **AND** 用户无需从两条长度不同的原始日志中自行寻找对应关系

#### Scenario: 根据能力选择焦点阶段
- **WHEN** 页面形成完成态阶段对照
- **THEN** Understand 始终包含获得信息和形成结论，Act 还包含采取行动和执行验证，Prove 还包含采取行动、执行验证和接收反馈
- **AND** 任一侧实际产生事件的其他阶段也加入对照

#### Scenario: 省略无关的空阶段
- **WHEN** 某阶段两侧均无事件且不属于所选能力的焦点阶段
- **THEN** 默认讲解视图不显示该阶段
- **AND** 完整记录仍保留所有实际产生的结构化事件

#### Scenario: 可见阶段的一侧没有事件
- **WHEN** 某个可见阶段只有一侧产生事件或焦点阶段没有可用事件
- **THEN** 缺失侧显示“未提供该能力”“本次未执行”或“暂无证据”等基于事实的中性说明
- **AND** 只有结构化结果证明首轮验证通过时才将缺少反馈说明为“无需反馈”

#### Scenario: 移动端查看阶段对照
- **WHEN** 视口不足以并排展示两条轨道
- **THEN** 页面按阶段展示包含 PLAIN 与 HARNESS 两侧摘要的纵向对照卡片
- **AND** 最终结论和两侧关键指标无需切换标签即可同时读取

#### Scenario: 查看类型化证据
- **WHEN** 用户展开具有证据的语义事件
- **THEN** 页面按照事件类型用带标签的字段、Diff 或纯文本日志展示经过后端脱敏和截断的数据
- **AND** 页面不以通用 JSON 作为默认证据表达

#### Scenario: 查看完整运行记录
- **WHEN** 用户选择查看完整记录
- **THEN** 页面在默认讲解内容之后展开同页独立区域，而不打开抽屉、模态框或新页面
- **AND** 区域按 sequence 展示两侧所有结构化事件及其可公开证据和事件元数据

#### Scenario: 筛选完整运行记录
- **WHEN** 用户在完整记录区域选择全部、PLAIN 或 HARNESS 筛选
- **THEN** 页面只显示符合筛选条件的事件并保留明确的运行侧标签
- **AND** 筛选不改变存储事件、阶段对照或最终结果

#### Scenario: 通过辅助技术开关完整记录
- **WHEN** 用户展开或收起完整记录区域
- **THEN** 触发控件通过 `aria-expanded` 和 `aria-controls` 暴露状态与目标区域
- **AND** 展开后的区域可被程序化聚焦，收起后焦点返回触发控件

### Requirement: 优先展示可验证且能力定制的本次运行结论
实验结束后，系统 SHALL 在详细过程之前展示带有“本次运行”限定语的自然语言观察、两侧终态以及与所选能力相匹配的对照指标。系统 SHALL 清楚区分已完成分析、仅生成提案、确定性验证通过、确定性验证未通过和基础设施异常，不得将单次真实 LLM 对照表述为统计结论，也不得以模型自述作为 PASS/FAIL 依据。

#### Scenario: 实验正常完成
- **WHEN** 后端返回两侧最终结果快照
- **THEN** 页面在过程详情之前展示本次运行观察、两侧可读终态和关键差异
- **AND** 页面明确说明结果来自本次运行而不是统计性 benchmark

#### Scenario: 展示 Understand 结果
- **WHEN** Understand 实验结束
- **THEN** 页面比较两侧输入来源、项目规则识别项和工作区未修改状态
- **AND** 将正常终态表达为“已完成分析”而不是代码验证 PASS 或未完成

#### Scenario: 展示 Act 结果
- **WHEN** Act 实验结束
- **THEN** 页面比较两侧是否仅提供建议、是否实际修改允许文件、是否执行固定测试以及最终验证状态
- **AND** 将 PLAIN 的正常基线表达为“仅生成代码建议”而不是失败

#### Scenario: 展示 Prove 结果
- **WHEN** Prove 实验结束
- **THEN** 页面比较两侧生成次数、测试次数、失败反馈次数和最终测试状态
- **AND** 在存在反馈修复时明确展示 TEST FAIL、FEEDBACK、修复和 TEST PASS 之间的因果顺序

#### Scenario: 单侧发生基础设施异常
- **WHEN** 一侧因配置、LLM API、连接或执行环境错误而终止
- **THEN** 页面将实验标记为不完整并将该侧显示为“实验运行异常”
- **AND** 不将异常显示为模型工程结果的 FAIL 或 Harness 能力差异

#### Scenario: 状态不能只靠颜色识别
- **WHEN** 页面显示任一终态或对照差异
- **THEN** 页面同时提供可读文本或图标标签
- **AND** 已完成分析和仅生成提案使用中性预期状态，不与验证失败共用错误语义
